# ระบบเติมสินค้า — คลังแม่กลอง

เว็บแอปสำหรับคำนวณยอดเติมสินค้าไปสถานี ผูกกับรอบรถจริง แล้วออกเทมเพลตสั่งซื้อ

React + Vite + Supabase — หน้าเว็บเป็น static ล้วน อ่านไฟล์ Excel ในเบราว์เซอร์โดยตรง ไม่ผ่านเซิร์ฟเวอร์ตัวกลาง

---

## ติดตั้งครั้งแรก

### 1. ฐานข้อมูล

ใน Supabase SQL Editor รันตามลำดับ:

1. `schema.sql` — ตาราง สูตรคำนวณ และ RLS
2. `migration_02.sql` — เพิ่มชนิดไฟล์ Master Item
3. `migration_03.sql` — ระบบผู้ใช้แบบชื่อผู้ใช้

### 2. ปิดการยืนยันอีเมล

Supabase › Authentication › Sign In / Providers › Email
ปิด **Confirm email**

จำเป็น เพราะระบบใช้อีเมลปลอม `ชื่อผู้ใช้@mgk.local` ถ้าเปิดไว้จะส่งเมลยืนยันไม่ได้ แล้วล็อกอินไม่ผ่าน

### 3. เปิดบัญชีผู้ดูแลคนแรก

เปิดหน้าเว็บ กด **เปิดบัญชีใหม่** ใส่ชื่อผู้ใช้กับรหัสผ่าน
แล้วกลับมารันใน SQL Editor แทนชื่อจริงลงไป:

```sql
update app_users set is_active = true, role = 'admin'
where username = 'somchai';
```

หลังจากนี้อนุมัติคนอื่นได้จากหน้า **ผู้ใช้** ในเว็บ ไม่ต้องกลับมาที่ SQL อีก

### 4. รันในเครื่อง

```bash
npm install
cp .env.example .env      # ใส่ค่าจาก Project Settings › API
npm run dev
```

### 5. ขึ้น GitHub Pages

```bash
git init && git add . && git commit -m "first"
git remote add origin https://github.com/<user>/<repo>.git
git push -u origin main
```

จากนั้นใน GitHub repo:

- **Settings › Secrets and variables › Actions** เพิ่ม 2 ค่า
  `VITE_SUPABASE_URL` และ `VITE_SUPABASE_ANON_KEY`
- **Settings › Pages** เลือก Source เป็น **GitHub Actions**

push ครั้งถัดไปจะ deploy อัตโนมัติ

> GitHub Pages บนบัญชีฟรีใช้ได้กับ repo สาธารณะเท่านั้น โค้ดจะเปิดเผย
> ข้อมูลยังปลอดภัยเพราะอยู่หลัง auth และเปิด RLS ไว้
> ถ้าต้องการ repo ส่วนตัว ใช้ Cloudflare Pages แทนได้ ฟรีเหมือนกัน
>
> **ห้ามใส่ `service_role` key ในโค้ดหน้าเว็บ** เพราะข้าม RLS ได้ทั้งหมด
> ใช้ `anon` key เท่านั้น

## บัญชีผู้ใช้

ล็อกอินด้วย **ชื่อผู้ใช้กับรหัสผ่าน** ไม่ต้องใช้อีเมล
เบื้องหลังระบบต่อ `@mgk.local` ให้เอง เปลี่ยนโดเมนได้ที่ `DOMAIN` ใน `src/views/Login.tsx`

เปิดบัญชีเองได้จากหน้าล็อกอิน แต่จะยังไม่เห็นข้อมูลจนกว่าผู้ดูแลจะกดอนุมัติ
RLS บังคับไว้ที่ฐานข้อมูล ไม่ใช่แค่ซ่อนหน้าจอ — บัญชีที่ยังไม่อนุมัติดึงข้อมูลไม่ได้เลยแม้เรียก API ตรง

| สิทธิ์ | ทำอะไรได้ |
|---|---|
| เจ้าหน้าที่ | นำเข้าข้อมูล คำนวณ ดู KPI |
| ผู้ดูแล | ทั้งหมด บวกแก้ค่าคำนวณ และอนุมัติผู้ใช้ |

## ลำดับการใช้งานประจำรอบ

**นำเข้าข้อมูล** ตามลำดับนี้ ครั้งแรกต้องครบทุกไฟล์

| ลำดับ | ไฟล์ | ได้อะไร |
|---|---|---|
| 1 | Master Item | ลิตรต่อชิ้น — สูตรหารด้วยค่านี้ ไม่มีคือคำนวณไม่ได้ |
| 2 | POWER_BI | สต็อกรายสาขา + สร้างรายชื่อสาขาอัตโนมัติ |
| 3 | ME2N | ของระหว่างทาง หักออกจากยอดสั่ง |
| 4 | WMS | สต็อกคลัง จำกัดไม่ให้สั่งเกินของที่มี (ไม่อัปก็คำนวณได้) |
| 5 | เที่ยวรถ | สาขาที่รถเข้ารอบนี้ |

รอบถัดไปอัปเฉพาะ 2–5 ก็พอ Master Item อัปเมื่อมีสินค้าใหม่

**คำนวณ** เลือกวันรถออก กดคำนวณ ตรวจรายการ ปรับยอดรายบรรทัดได้ แล้วดาวน์โหลดเทมเพลต

## สูตรที่ใช้

```
ยอดขาย/วัน  = ยอดขายลิตร 30 วัน ÷ ลิตรต่อชิ้น
CoverDay    = MAX(รอบส่งจริงของสาขานั้น × 1.15 , rop_min)
เป้าหมาย     = ยอดขาย/วัน × (CoverDay + LeadTime) + SafetyStock
ยอดสั่ง      = CEIL(เป้าหมาย − คงเหลือ − ระหว่างทาง)
```

**จุดต่างจากไฟล์ Excel เดิม** — เดิม CoverDay คงที่ 4 วันทุกสาขา รวมกับ LeadTime 3 เป็น 7 วัน
แต่รถเข้าสาขาจริงห่างกันตั้งแต่ 1 ถึง 28 วัน สาขาที่รถเข้าทุก 14 วันจึงของหมดกลางรอบ
ตอนนี้ CoverDay ดึงจากประวัติเที่ยวรถ 120 วันของสาขานั้นเอง (`v_station_cycle`)

**เรื่องเพดาน DOH** — มีสวิตช์ `doh_cap_enabled` ปิดไว้เป็นค่าเริ่มต้น
เปิดแล้ว availability จะแย่ลง เพราะราว 15% ของรายการขายช้าจนวางแค่ 1 ชิ้นก็เกิน DOH 25 ทันที
DOH ต้องลดด้วยการดึงของค้างออก ไม่ใช่การสั่งน้อยลง — ถ้าหยุดสั่งทั้งเดือน DOH ก็ยังเกินเป้าอยู่ดี

**ลำดับความสำคัญ** ตอนของคลังไม่พอ ระบบจัดสรรตามนี้ ไม่ใช่ใครมาก่อนได้ก่อน

1. ขาดจริง — สต็อก 0 แต่มียอดขาย
2. เสี่ยงขาดก่อนรถถึง — DOH น้อยกว่า LeadTime
3. ไม่พอถึงรอบหน้า — DOH น้อยกว่า CoverDay
4. ปกติ

## ปรับค่าคำนวณ

หน้า **KPI และค่าคำนวณ** แก้ได้ทันที มีผลรอบถัดไป
รอบที่คำนวณไปแล้วเก็บค่าที่ใช้ตอนนั้นไว้ใน `calc_runs.params` ตรวจย้อนหลังได้เสมอ

| ค่า | ค่าตั้งต้น | ความหมาย |
|---|---|---|
| `rop_min` | 4 | CoverDay ขั้นต่ำ กรณีไม่มีประวัติรอบส่ง |
| `lead_time` | 3 | สั่งถึงของถึงสาขา |
| `cycle_buffer` | 1.15 | ตัวคูณกันรอบรถคลาด |
| `ss_class_a/b/c` | 2 / 1 / 0 | Safety stock รายคลาส |
| `doh_ceiling` | 25 | เส้น KPI ใช้แสดงผลและใช้ตอนเปิดเพดาน |
| `doh_cap_enabled` | 0 | เปิดเพดาน DOH ตอนคำนวณ |

## เมื่อรูปแบบไฟล์เปลี่ยน

ตัวอ่านไฟล์อยู่ใน `src/lib/parsers.ts` ที่เดียว จับคู่หัวตารางแบบตัดช่องว่างและไม่สนตัวพิมพ์
ถ้าไฟล์ใหม่หัวตารางเปลี่ยน เพิ่มชื่อทางเลือกในฟังก์ชัน `c(...)` ของไฟล์นั้นได้เลย
เช่น `c('คงเหลือ(ลิตร)', 'ยอดคงเหลือลิตร')`
